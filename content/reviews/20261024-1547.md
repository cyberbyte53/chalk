## Plan

All three comments say the same thing about the `valueMachine` prop: x moves in whole steps only, and the way you put a number in feels clumsy. Right now you press − or + once for every whole number (going from 0 to −5 takes five taps). Each tap already puts the number in, so the "→" button only puts the same number in again, and the grid below is just for looking at. **The fix goes in the prop**, so it reaches all three boards that use it.

**Prop change (`library/props/polynomials`, valueMachine):**
1. **Drag x along the grid's x-axis.** A handle sits on the x-axis. While you drag it, the working (p(2.3) = …) updates live and a hollow marker rides on the curve's point (x, p(x)). When you let go, a dot is left there. This is a new learner action, `move {x}`, which leaves no dot. `put {x}` stays as it is (a dot, plus the `put` and `foundZero` signals), so the rules and witnesses on the boards don't change.
2. **Finer steps.** The default step becomes 0.1, and the handle snaps to it. The − / + buttons stay as fine nudges, and each nudge puts the number in. The "→" button goes.
3. **Decimals are written as decimals.** Today 2.3 would come out as 23/10. Inputs like 2.3, and values like −3.61, will print as decimals, while ½ and ¼ stay as fractions (the cubic board needs (½)³ = 1/8).
4. README, law tests for `move` and decimal working, `pnpm catalogue`.

**Boards:**
- [value](board:class10-maths/polynomials/value-and-zeroes/overview/value) — takes the new input and the 0.1 step; `move` joins `studentOnly` (comments cmvmkog1eu18, cmvmkpdy7fos, cmvmmafyodme)
- [zeroes](board:class10-maths/polynomials/value-and-zeroes/overview/zeroes) — same; the hunt for 4 still ends when 4 is put in (the handle snaps to 4.0, or you nudge to it)
