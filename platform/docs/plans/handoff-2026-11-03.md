## Labels (done)

`platform/docs/plans/labels-simple.md` holds the design and every measurement. In short: a label
names one thing (`useLabel(ref, () => ({ own: thing, prefer: LabelSide.Above }))`, in
`@chalk/draw`); it keeps off everything drawn but what is `data-coverable` (grid, tints, roads,
ticks, place pictures); its cost grows with distance from its thing; it sits clearly nearer its
own thing than any other; all labels are solved together (exact for small groups, annealing
otherwise, after pruning spots that can't win). Weights and their rules: `label-weights.ts`.
The audit: `pnpm label-compare run <name> [--quick]` in `platform/studio` (script in
`platform/studio/scripts/`). 618 drawings: 20 with any problem, none on another label.

## Next: the learner model, the teacher view, Jugnu

The person wants: a learner model that turns what a child does into how well they understand
each concept; a teacher view showing where each student is strong or weak; and Jugnu (the AI
tutor) rebuilt on the board model — all standing on one clean data pipeline. Start with the
pipeline, from first principles, as a plan.

### The data pipeline today (inventory)

- **Phone**: `recordBoard` (`packages/player/src/recorder.ts`) records learner causes and
  signals with an envelope `{id, schemaVersion 2, session, seq, at, commit, actor, opening,
  board, version, node}`; kinds `open/close/cause/signal/jugnu/app`
  (`packages/content/src/event.ts`). The uploader (`apps/learner/src/uploader.ts`) keeps them in
  IndexedDB and sends batches of 200 to `POST /api/events`.
- **Server**: `events` table (`apps/server/src/schema.ts`), keyed by (account, id). One processor,
  `boardFactsFrom` (`packages/api/src/progress.ts`), keeps `board_facts`: per (account, board)
  passed_at, first_at, first_is_right. Progress and mastery are computed on the fly from it
  (`progressFrom`; `mastery.ts`, uncommitted: a Beta per concept from first tries, weighted by
  level). Teacher view: `apps/learner/src/teacher-screens.tsx` (concept squares per learner).
- **Accounts**: Google sign-in; accounts with role learner/teacher, schools, groups with join
  codes, members.

### Gaps found

- **Which concept an answer evidences** is worked out by joining the board id to the *current*
  build's `tests`; a later build silently re-reads old answers. Question level isn't in events.
  Objectives (o1…) aren't in built content at all.
- **Facts are per board, not per question**, ignore the version, and use only the first try;
  later attempts and chosen options aren't used.
- **Two notions of "how well"**: concept squares use the mastery band, "weakest concept" uses
  right/of; the docs describe neither accurately.
- **Shared phones mix accounts**: the phone's event store isn't per account (unsent events go up
  under the next account; local progress mixes users).
- **Privacy for minors**: every event kept forever, no deletion or retention, no consent field;
  backups only on the box; a teacher sees a learner's progress in every course.
- `platform/docs/plans/events-and-names.md`, which `events.md` cites, doesn't exist.
- Jugnu leftovers: the `jugnu` event kind and `Actor.Jugnu` remain; server README lists removed
  routes; `jugnu_flags` table unused.

### Jugnu, from the parked code (`parked/`, evals in `library/props-later/jugnu-evals`)

He came only when called (a button, hold-to-ask on a part, "why was I wrong?"); saw the board as
data; tried things on a hidden copy; replied by saying, pointing at a part, or acting through the
board's one door; the runtime refused his never-list (answer or check the question, pass the
board, say the lesson's lines). Evaluations: the main risk is giving the answer away; private
reasoning fixed most leaks; holding back everything hurt learning (answer concept questions
plainly, hold back only the board's answer, step up help when a student loops). Open: slow calls,
a weak judge (same model), privacy of children's chats. The new board model gives him parts by
name, `describeView`, events; it lacks a Jugnu actor path and save/restore for trying things.
